# Milestone 4: Runs and the Sessions View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Launch one Claude Code session per task in its own worktree, watch every run stream into a card in a full-width sessions view, message and stop it, see its PR link appear, resume runs interrupted by a restart, and see the repository's other Claude Code sessions beside them.

**Architecture:** A run is a `PlanSession` (the milestone 1 session class, reused unchanged) whose working directory is a worktree under `.blueprint/worktrees/<slug>` on branch `blueprint/<slug>`, started with the run prompt and `permissionMode: "acceptEdits"` by default, without the board tools. A `RunManager` owns every run: it creates the worktree with git, starts the session, derives the run's status from the session's status and result events, picks the PR URL out of the final text, persists `RunRecord`s through a serialized `sessions.json` writer, and broadcasts run events and statuses over the WebSocket. Dependency gating is a local git ancestor check with an override. The sessions view renders a card per run with the same transcript and permission components the panel uses, plus a read-only list of the repository's other sessions from the SDK's session listing.

**Tech Stack:** The milestone 3 stack; `git` through `execFile` (worktrees, ancestor checks); the SDK's `listSessions` and `getSessionMessages`. No new dependencies.

**Spec:** `docs/build-plan.md` (sections 4, 5 `sessions.json` and `worktrees/`, 6.7, 7, 8 row 4, 9, 10). Milestones 1 to 3 are on `main`; this plan builds on `PlanSession`/`SessionDeps`, `PermissionBroker`, `SdkEventMapper`, `FileStore.readSessions/writeSessions`, `RunRecord`/`RunStatus`/`SessionsFile`, `TaskFile` and `FileStore.listTasks/readSpec`, `agentRoutes`, `ClaudePanel`'s transcript and `PermissionDialog`, `useHashRoute`, `Sidebar`, and `TasksView`.

Calls made for this plan where the spec is silent:

- `PlanSession` is reused as the run session class; a run differs only in `cwd`, options, and the first message. No subclass.
- Run status is derived, not stored separately: `working` while the session works or starts, `needs_you` while its broker has a pending ask, `idle` after a result without a PR URL, `done` after a result whose text carries a PR URL (or when the user marks nothing: the spec's "PR or summary" reads as the PR URL being the signal, since every run ends with a summary), `failed` on an error status, `interrupted` for runs that were active when the server started. The persisted record carries the last derived status so the view can show it before the session exists.
- The PR URL is the first line of the final assistant text that is only a GitHub pull-request URL.
- `sessions.json` writes are serialized through one promise chain in a `RunStore`, which also owns the plan session id write (closing the milestone 1 ponytail note).
- Worktrees are created from the current `HEAD` of the repository and never removed by Blueprint; the spec leaves cleanup to the user.
- A resumed run sends `Continue the task where you left off.` as its first message.
- "Open in terminal" is a copy button for `claude --resume <sessionId>` run from the worktree path, shown next to it.

## Global Constraints

- Node 22.1 or later; TypeScript strict; ESM; server code uses NodeNext resolution with explicit `.js` extensions on relative imports.
- No API key anywhere. Every run is an ordinary Claude Code session on the user's login.
- Worktrees live at `.blueprint/worktrees/<slug>` on branch `blueprint/<slug>`, created from the repository's current `HEAD`; both paths are git-ignored by `blueprint init`.
- Run sessions get no board tools; their context is the task file and the spec.
- Run permission mode defaults to `acceptEdits`; the launch dialog offers `default` and `bypassPermissions`; whatever still prompts shows as a dialog in the sessions view.
- Launch is gated: every `dependsOn` task needs a run with status `done` whose branch is an ancestor of `HEAD`; the dialog explains what is missing and offers an override.
- Run status is one of `working`, `needs_you`, `idle`, `done`, `failed`, `interrupted`.
- All agent output reaches the browser as typed WebSocket messages; commands go through HTTP routes so they are testable with `app.request()`.
- No "Claude Code" branding in UI copy, except the literal `claude --resume` command the copy button produces.
- Every UI test file that renders components or hooks starts with `// @vitest-environment jsdom`.
- Commit messages use conventional commits and carry no co-author trailer.
- `pnpm check` stays pristine; `pnpm build` warns only about the pre-existing chunk size.

## Review Focus

1. Launching a task whose worktree or branch already exists (a previous run, a crash mid-create): the launch must fail with a message naming the path or branch, not corrupt git state. Pinned in Task 1.
2. The server restarts while two runs are working: both show `interrupted` with a Resume button, resuming continues the same session id in the same worktree, and nothing is relaunched twice. Pinned in Task 3 and Task 4.
3. A run's permission ask arrives while the sessions view is closed: it waits, shows when the view opens, and Stop cancels it. Pinned in Task 3 and Task 6.
4. Several runs stream at once: events and statuses carry the run id and never cross cards, and the shared rate limit note is visible. Pinned in Task 3 and Task 6.
5. `gh` is not installed or the push fails: the run ends `idle` with Claude's explanation and no PR link, never `done`. Pinned in Task 2 and Task 3.

### Task 3: The run manager

**Files:**
- Create: `src/server/runs/manager.ts`
- Modify: `src/shared/messages.ts`
- Test: `test/server/runs/manager.test.ts`

**Interfaces:**
- Consumes: `RunStore`, `createWorktree` (Task 1), `runPrompt`, `prUrlIn` (Task 2), `PlanSession`, `PermissionBroker`, `denyBoardWrites`, `FileStore.listTasks/readSpec`, `WsHub.broadcast`.
- Produces in `src/shared/messages.ts`, added to `ServerMessage`:

```ts
| { type: "run.event"; runId: string; event: PanelEvent }
| { type: "run.status"; runId: string; status: RunStatus; message?: string }
| { type: "runs.changed" }   // a record was added or patched; clients refetch GET /api/runs
```

- Produces in `src/server/runs/manager.ts`:

```ts
export type LaunchOptions = { taskSlug: string; permissionMode: "acceptEdits" | "default" | "bypassPermissions" };
export type RunView = RunRecord & { pending: PendingPermission[]; lastText: string | null };
export class RunManager {
  constructor(deps: { store: FileStore; runs: RunStore; hub: WsHub; root: string; sdk: Pick<typeof claudeSdk, "query" | "getSessionMessages">; git?: { createWorktree: typeof createWorktree } });
  start(): Promise<void>;                                   // marks records that were working or needs_you as interrupted and broadcasts runs.changed
  launch(opts: LaunchOptions): Promise<RunRecord>;          // throws NotFoundError for an unknown task; creates the worktree, the record (status working), starts the session, sends the run prompt
  message(runId: string, text: string): Promise<string>;    // throws NotFoundError; a done or failed run accepts it (the session resumes)
  stop(runId: string): Promise<void>;                        // cancels asks, interrupts; status follows the session
  resume(runId: string): Promise<void>;                      // only for interrupted runs: starts a session with resume in the worktree and sends the continue message
  answerPermission(runId: string, id: string, d: PermissionDecision): boolean;
  list(): RunView[];
  transcript(runId: string): PanelEvent[];
  close(): Promise<void>;                                    // closes every session; records keep their last status (they read interrupted on the next start)
}
```

  Status derivation per run: session `starting`/`working` → `working`; broker pending → `needs_you`; session `idle` → `done` if the last assistant text of the turn had a PR URL (also sets `prUrl`, `endedAt`), else `idle`; session `error` → `failed` with the message, `endedAt`; session `stopped` → `idle`. Each `result` event updates `costUsd` from the event. Every derived change patches the record and broadcasts `run.status`; every event broadcasts `run.event` with the run id. Run sessions use `systemPrompt: { type: "preset", preset: "claude_code" }` with no append, `permissionMode` from the launch, `hooks` with `denyBoardWrites(worktree)`, no `mcpServers`, and the broker's `canUseTool`.
