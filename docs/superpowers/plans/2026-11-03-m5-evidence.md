# Milestone 5: Evidence and Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Blueprint is ready to show: a fake-SDK mode lets anyone run it without a subscription, Playwright covers the three headline flows and records the demo, a design pass gives the UI one coherent look with rendered Markdown, the README explains setup and the login caveat, and the polish backlog from milestones 1 to 4 is cleared.

**Architecture:** A fake Agent SDK selected by `BLUEPRINT_FAKE_SDK=<scenario.json>` replaces `query`, `getSessionMessages`, and `listSessions` in `startServer`; it replays scripted turns, can call Blueprint's own MCP tools, can write files the way Claude's Write tool would, and returns structured output for the split. Playwright drives the built CLI against that fake in a temporary git repository and records video. The design pass writes `DESIGN.md` and moves every color, size, and radius in `styles.css` onto tokens. A small React Markdown renderer (no dependency, no `innerHTML`) shows assistant text. The backlog is fixed task by task.

**Tech Stack:** The milestone 4 stack plus `@playwright/test` 1.64 as a dev dependency.

**Spec:** `docs/build-plan.md` (sections 7, 8 row 5, 9, 10, 11). Milestones 0 to 4 are on `main`.

Calls made for this plan where the spec is silent:

- The demo is the Playwright run's video against the fake SDK, saved under `docs/demo/`, because a recording with a real login cannot be reproduced and spends the user's allowance. The README links it.
- The fake SDK is production code (it ships in the package) because the spec's section 9 asks for it to drive "local UI work", and decision 2 in section 11 names a demo mode for people without a subscription.
- Markdown rendering covers paragraphs, headings, emphasis, inline code, fenced code, lists, links, and block quotes; anything else is shown as text. Links open in a new tab with `rel="noreferrer"`.

## Global Constraints

- Node 22.1 or later; TypeScript strict; ESM; server code uses NodeNext resolution with explicit `.js` extensions on relative imports.
- No API key anywhere. With `BLUEPRINT_FAKE_SDK` unset, behaviour is unchanged.
- No "Claude Code" branding in UI copy; the README may name Claude Code as the thing Blueprint runs beside.
- Every UI test file that renders components or hooks starts with `// @vitest-environment jsdom`.
- Commit messages use conventional commits and carry no co-author trailer.
- `pnpm check` stays pristine; `pnpm build` warns only about the pre-existing chunk size; `pnpm e2e` passes three times in a row.
- Long Markdown files put each full sentence on its own line, and never use an em dash.

## Review Focus

1. The fake SDK must not leak into a real run: with the variable unset the real SDK is used, and with it set every session (plan, split, runs) uses the fake. Pinned in Task 1.
2. Playwright flakiness: no fixed sleeps; every wait is on visible state; the suite passes three runs in a row. Pinned in Task 2.
3. The Markdown renderer must never execute or inject HTML from Claude's text. Pinned in Task 3.
4. The restyle must not regress layout at the default window size or at 1280 by 800: no overlap of the proposals bar, the panel header, or the run cards. Pinned in Task 3's screenshots and Task 6.
5. The README's setup steps must work from a fresh clone. Pinned in Task 6.

### Task 1: Fake SDK mode

**Files:**
- Create: `src/server/fake/sdk.ts`, `src/server/fake/scenario.ts`, `e2e/scenario.json`
- Modify: `src/server/index.ts`, `src/server/agent/index.ts`, `src/server/runs/manager.ts`, `src/server/sessions.ts` (accept injected SDK functions where they do not already)
- Test: `test/server/fake/sdk.test.ts`

**Interfaces:**
- `src/server/fake/scenario.ts` defines the scenario file with Zod:

```ts
const Step = z.discriminatedUnion("do", [
  z.object({ do: z.literal("say"), text: z.string() }),
  z.object({ do: z.literal("tool"), server: z.literal("blueprint"), name: z.string(), input: z.record(z.string(), z.unknown()) }),
  z.object({ do: z.literal("write"), path: z.string(), content: z.string() }),   // relative to the session cwd
  z.object({ do: z.literal("ask"), tool: z.string(), input: z.record(z.string(), z.unknown()) }),   // goes through canUseTool
]);
const Rule = z.object({ match: z.string(), steps: z.array(Step), costUsd: z.number().default(0.01) });   // match: a regex tested against the user message
const Scenario = z.object({ plan: z.array(Rule), run: z.array(Rule), split: z.object({ tasks: z.array(z.unknown()) }) });
```

- `createFakeSdk(scenarioPath: string): { query; getSessionMessages; listSessions }` with the SDK's signatures. `query` emits an init message, then for each user message the first matching rule's steps as SDK messages (stream deltas and assistant text for `say`; a tool_use and its result for `tool`, calling the blueprint MCP server instance from `options.mcpServers.blueprint`; a Write tool_use plus the file write for `write`; `ask` awaits `options.canUseTool` and reports allow or deny), then a success result with `costUsd`. With `outputFormat` set it returns `structured_output` from `split`. Sessions are kept in memory so `getSessionMessages` and resume work within one server process; `listSessions` returns `[]`.
- `startServer` reads `process.env.BLUEPRINT_FAKE_SDK` once; when set it logs `Using the fake SDK from <path>` and passes the fake to the agent, the split, the run manager, and the sessions routes.
- `e2e/scenario.json` scripts the three flows: an ask that proposes a two-node flowchart; a compile that writes a two-section spec with one board citation; a split of two tasks; a run turn that writes one file and ends with a PR URL line.

- [ ] **Step 1: Write the failing tests** (scenario parsing errors name the bad step; a `say` rule streams text and ends with a result; a `tool` rule calls the blueprint tool and reports its result; a `write` rule writes the file under cwd and refuses paths outside it; an `ask` rule goes through canUseTool; structured output for the split; resume replays the in-memory transcript)
- [ ] **Step 2: Run them to verify they fail**
- [ ] **Step 3: Implement**, then verify by hand: `BLUEPRINT_FAKE_SDK=e2e/scenario.json node dist/cli/index.js --no-open` in a scratch repo; ask, accept, compile, split, launch, and see each step complete with no real Claude process.
- [ ] **Step 4: `pnpm check`**, pristine.
- [ ] **Step 5: Commit** `feat(server): a fake SDK mode that replays a scenario`

### Task 4: Polish backlog

**Files:** as each item needs; tests beside each change.

Fix each of these, test first where it is behaviour:

1. The sidebar drops a board or doc deleted on disk (refetch the lists on an `unlink` file-changed event).
2. `Allow always` is labelled `Allow for this session` when the SDK sent no permission suggestions, so it never promises more than it does.
3. Tool rows for `ToolSearch` read `loading tools`, and a non-text tool result reads `done` instead of `(non-text result)`.
4. The sessions view's other-session transcript and the launch dialog's gate snapshot refresh on `runs.changed`; the launch dialog shows the branch name the server will use (from the gate response, not rebuilt in the UI).
5. `RunStore`: test `newRunId`'s retry against a stored run, a write after a failed write, and `isAncestor`'s re-throw.
6. A failed run's `endedAt` does not move when only its failure message changes; test a restored failure reason through a re-derive.
7. `compile()` reads docs with skip-and-warn like boards, so one unreadable doc does not fail the compile.
8. Stop shows `Stopping…` on the button between the click and the interrupt landing (Stop takes several seconds).

- [ ] **Step 1 per item: failing test, fix, passing test.**
- [ ] **Step 2: `pnpm check` and `pnpm e2e`.**
